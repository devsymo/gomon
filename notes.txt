I've built gomon: a Go rewrite of Xymon that compiles to one binary with the React/shadcn UI embedded (like qui), stores data in PostgreSQL, and accepts unmodified Xymon clients. I tested it against Upstream Xymon's own client, compiled from source: it worked over plain Xymon, over TLS, and through the relay. The one thing I couldn't test is the Docker image and `docker-compose.yml`, because the Docker daemon wasn't running. For testing I used a throwaway local Postgres.

**Existing agents and plugins**
- **Plain Xymon:** gomon listens on 1984 and handles the standard message types (status, combo, client, data, queries, disable/enable, ack, drop and the rest). Hosts register themselves the first time they report.
- **Your config files:** you can keep using `analysis.cfg` (thresholds for cpu, disk, inode, memory, processes, ports and logs) and `client-local.cfg`. `hosts.cfg` can be imported from the UI or the command line.
- **Plugins** keep calling `$XYMON $XYMSRV "status …"`. Plugin output in the `name : value` form is also graphed, as Xymon does.

**Encryption**
- Port 1985 speaks the TLS mode that Xymon 4.3.32 introduced (`xymons://`), so recent Xymon clients can encrypt with a config change only.
- gomon has its own certificate authority. It issues the server certificate and per-host client certificates, either from the UI or with `gomon cert issue` / `gomon cert sign`.
- A client with a certificate can only report for the host its certificate names. In testing, an attempt to report as a different host was rejected.
- For older agents (BBWin, devmon, older scripts), `gomon relay` runs on the monitored host, accepts plain messages on 127.0.0.1:1984 and forwards them encrypted. No client changes are needed.
- `gomon send`, or the binary symlinked as `xymon`, is a drop-in replacement for the `xymon` command and also supports `xymons://`.

**Tested with real clients and devices**
- Xymon's own `xymon` command, sending plain, sending over TLS with client certificates, and going through the relay.
- Xymon's full client script on this Mac, sending real OS data over TLS. gomon's memory check gave the same result as Xymon's: swap at 89% is red.
- SNMP v2c against the `snmpd` that ships with macOS: system info, custom OIDs with thresholds, and 23 interfaces with traffic rates. v1/v2c/v3 are supported, but v3 hasn't been tested against a live agent.
- Built-in network tests (ping, TCP services, closed-port checks, HTTP status and content checks, certificate expiry), alert rules (Slack, Discord, ntfy, email, webhook), and OIDC login. The OIDC code is written but I haven't run it against a real identity provider.
- I checked every page in headless Chrome, in light, dark and mobile layouts.

**UI:** The layout follows qui: sidebar and header, light/dark/system mode, and qui's own free themes. It has a dashboard with a Xymon-style host-by-check grid, hosts, per-check pages with history and graphs, raw client data, events, SNMP, alerts, and settings.

**Things you should know**
- **License:** I copied qui's theme files so the look matches exactly. They are GPL-2.0-or-later, so I added a GPL `LICENSE` (Xymon is GPL-2 too). If you don't want GPL, I can remove those themes and write our own.
- **Not built yet:** importing history from old RRD files, the `alerts.cfg` format (alerts are set up in the UI instead), xymonnet's dns/ldap/ntp tests, SNMP traps, reports/SLA pages, and the analysis.cfg rules `FILE`, `DIR`, `SVC` and `LINECOUNT` (gomon accepts them but doesn't evaluate them yet).
- **Build:** this shell's default Node is v18, which is too old for the frontend build. Building needs Node 20.19+ (your nvm v24 works) and Go 1.26.
- I ran `git init` but haven't committed anything.

To run it: `docker compose up -d --build`, then open http://localhost:8080 and create the admin account. Without Docker: `make web build`, then `bin/gomon serve`. The README covers TLS rollout, the relay, SNMP and OIDC setup.





I've added both pages. They're in the sidebar as Non-green and Pages. I tested them against an imported multi-level hosts.cfg in light and dark mode, with no browser console errors.

Non-green (/nongreen) — the equivalent of Xymon's "all non-green" page.

The banner at the top takes the colour of the worst check, with counts like "3 critical · 3 warning".
Hosts are grouped by page, worst first. Each group only shows the columns that have a problem, but those columns still show the host's green checks for context.
Filter chips choose which colours count as a problem (red, yellow and stale are on by default; blue and clear are optional). The choice is remembered in the browser. There's also a "Hide acknowledged" switch.
When nothing matches it shows "Everything is green".
Pages (/pages/...) — the classic Xymon layout.

The top level shows a tile for each page, and each page shows tiles for its subpages, as deep as hosts.cfg nests them. Every tile and banner takes the worst colour of everything below it, with breadcrumbs back up.
Hosts are split into one table per group heading, and each group gets its own columns, as in Xymon. Column names are vertical and each check is a round icon, like Xymon's status GIFs.
An acknowledged problem shows a check mark on its icon, and a check that changed in the last hour gets a pulsing ring. Hovering an icon shows the summary; clicking it opens the status.
Backend changes

gomon used to drop hosts.cfg group lines and page titles, so headings and titles had nowhere to come from. Hosts now have a group field, and page titles are stored in their own table. Migration 002_groups_pages.sql adds both and runs automatically on startup.
The hosts.cfg import now reads page/subpage/subparent/group* lines, including deeper nesting. HTML in titles is stripped.
Exporting hosts.cfg (including config hosts.cfg over the protocol) writes all of that back out. A test checks it survives an export and re-import unchanged.
There's a new GET /api/pages endpoint for the titles.
The host settings form now has separate Page (e.g. linux/db) and Group heading fields. The page shown on a host's detail page links into the Pages view.
One difference from Xymon: groups on a page are listed alphabetically (ungrouped hosts first), not in their hosts.cfg order, because gomon doesn't store that order. If you want hosts.cfg order kept, I can add a sort-order column.
